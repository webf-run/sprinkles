An alert dialog interrupts to ask for a decision: delete these images,
publish this page, overwrite a newer version. It has a title, a message and
two or three buttons, and closes only through them (or Escape, which
cancels). A click outside does nothing.

Use it sparingly, for actions that are hard to undo or that affect other
people. For a task with a form, use a [Dialog](/overlays/dialog/); to report
something that already happened, a [Toast](/feedback/toast/).

## Variants

`variant='confirmation'` (default) gives an accent confirm button and puts
focus on it. `variant='destructive'` makes it negative and puts focus on
Cancel, so a quick Enter doesn't delete anything.

## Pending

Return a promise from `onConfirm`: the confirm button shows a spinner, the
other buttons and Escape are disabled, and the dialog closes when the
promise resolves. If it rejects, the dialog stays open so the person can
retry or cancel; report the error yourself (a [Toast](/feedback/toast/)
works well). For an action you track elsewhere, pass `pending`.

</ExampleBlock>

## Secondary action and controlled open

`secondaryLabel` adds a third choice. Here a save finds a newer version on
the server, so the app opens the dialog itself with `open` and
`onOpenChange`. `onCancel` runs for Cancel and for Escape.

## Sizes

`size` is `s` (384 px, the default) or `m` (512 px, the default when there's
a secondary action, so three buttons fit on one line).

## States

- **Open:** focus is on the confirm button, or on Cancel when destructive.
- **Pending:** the confirm button shows a spinner and keeps its width; Cancel
  and the secondary button are disabled; Escape is ignored.
- **Closing:** focus returns to the trigger, or to whatever had focus before.

## Accessibility

- Rendered with `role="alertdialog"` and `aria-modal="true"`; the title
  labels it and the message describes it, so screen readers read both.
- Focus is trapped inside; Tab cycles through the buttons.
- Escape cancels (except while pending). A click outside doesn't close it.
- While pending, the confirm button has `aria-busy` and stays focusable.

## Props

| Prop             | Type                                   | Default          |
| ---------------- | -------------------------------------- | ---------------- |
| `title`          | `JSX.Element`; required                |                  |
| `children`       | `JSX.Element`; the message             |                  |
| `variant`        | `'confirmation' \| 'destructive'`      | `'confirmation'` |
| `confirmLabel`   | `string`; required                     |                  |
| `onConfirm`      | `() => unknown`; may return a promise  |                  |
| `cancelLabel`    | `string`                               | `'Cancel'`       |
| `onCancel`       | `() => void`; Cancel or Escape         |                  |
| `secondaryLabel` | `string`                               |                  |
| `onSecondary`    | `() => void`                           |                  |
| `pending`        | `boolean`                              | `false`          |
| `size`           | `'s' \| 'm'`                           | `'s'`            |
| `trigger`        | `(props: TriggerProps) => JSX.Element` |                  |
| `open`           | `boolean`; controlled                  |                  |
| `defaultOpen`    | `boolean`                              | `false`          |
| `onOpenChange`   | `(open: boolean) => void`              |                  |
| `class`          | `string`                               |                  |
