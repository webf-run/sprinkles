A badge labels something: a page's status, a document's category, a section's
eyebrow. It isn't interactive; for something people press, use a
[Button](/actions/button/).

## Semantic variants

When the label carries meaning, use a semantic role: the colour then means
the same thing everywhere (green is always "done", red is always "wrong").

## Categorical variants

When the colour only tells categories apart, use a categorical colour. They
carry no meaning, so they never compete with a status.

## Fill style

`subtle` (default) is a quiet tint. `bold` is a solid fill for the few labels
that must stand out. `outline` draws only the border.

</ExampleBlock>

## Sizes

Badges are labels, not controls, so they sit half a step below the control
scale: S, M, L and XL are 20, 24, 28 and 32 px tall.

</ExampleBlock>

## Static colour

Over photos or a coloured band, `staticColor='white'` or `'black'` ignores the
theme. The subtle fill turns into frosted glass.

<ExampleBlock code={staticColorCode}>
  <StaticColorOutput />
</ExampleBlock>

## Accessibility

- A badge is plain text in a `<span>`; screen readers read its label in
  place. Don't rely on colour alone: the label must say the status.
- Text and fill pass 4.5:1 in every variant and fill style in the default
  theme (`pnpm check:tokens`).
- The icon is hidden from screen readers, since the label already says it.

## Props

| Prop          | Type                                           | Default     |
| ------------- | ---------------------------------------------- | ----------- |
| `variant`     | a role, `'highlight'`, or a categorical colour | `'neutral'` |
| `fillStyle`   | `'bold' \| 'subtle' \| 'outline'`              | `'subtle'`  |
| `size`        | `'s' \| 'm' \| 'l' \| 'xl'`                    | `'m'`       |
| `staticColor` | `'white' \| 'black'`                           |             |
| `icon`        | a lucide-solid icon                            |             |
