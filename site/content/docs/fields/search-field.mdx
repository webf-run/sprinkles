A search field lets people type a search query and clear it again. It has a
magnifier at the start and, once there is text, a button to clear it. For other
single-line text, use a [TextField](/fields/text-field); to pick one value from
a list of matches, a [Combobox](/fields/combobox).

## Value

Use `value` to control the text, or `defaultValue` to set a starting value and
let the field keep it. `onValueChange` receives the new text each time it
changes. `onSubmit` receives the text when the user presses Enter, so you can
search on submit instead of on every keystroke.

## Clearing

The clear button and the Escape key both empty the field. `onValueChange` is
called with an empty string, then `onClear` is called, and focus moves back to
the input. Escape does nothing while the field is empty, so it still closes a
dialog or popover the field sits in. A disabled or read-only field has no clear
button.

The button is named "Clear search" for screen readers. Use `clearLabel` to
translate it. It is as wide as the field is tall and follows the field's
rounded end, like the stepper buttons of a [NumberInput](/fields/number-input).

## Forms

Use `name` to submit the text with a form. Pressing Enter inside a `<form>`
submits the form as well as calling `onSubmit`. Set `required`, `minLength`,
`maxLength` or `pattern` to validate with the browser, or set `invalid` and
`errorText` to show your own client or server-side error.

## Types

`type` is `search` by default, which gives phones a search keyboard. Set it to
`text`, `url`, `tel`, `email` or `password` when the query has a known format.
`enterKeyHint` sets the label or icon on a phone's Enter key and is `search` by
default. `inputMode` picks the keyboard without changing the input's type.

## Sizes

S, M, L and XL are 24, 32, 40 and 48 px tall, the same scale as buttons and
other fields, so a search field and a button side by side line up. M is the
default.

## States

Hover darkens the outline; keyboard focus draws the focus ring. Invalid turns
the outline negative and shows `errorText`. Disabled is greyed out and skipped
by the Tab key. Read-only sits on a muted surface; it can be focused, selected
and copied.

## Accessibility

- A native `<input>`, so typing, selection and spell check work as people
  expect. `enterKeyHint`, `inputMode` and `spellCheck` pass through to it.
- The label names the input, and the description or error describes it; see
  [Field](/fields/field). A search box often has no room for a visible label;
  give it `aria-label` instead.
- The search icon is decorative (`aria-hidden`).
- The clear button has an accessible name and stays out of the Tab order.
  Keyboard users clear with Escape, so there is no extra stop between the field
  and the next control.
- The outline is `border-strong`, which reaches 3:1 against the page.

| `enterKeyHint`                                | `'enter' \| 'done' \| 'go' \| 'next' \| 'previous' \| 'search' \| 'send'`             | `'search'`       |

| `aria-label`                                  | `string`; required without a visible label                                            |                  |
