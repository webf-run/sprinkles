```tsx
import { Field, type FieldOptions } from '@webf/sprinkles';
```

Every field (TextField, TextArea, NumberInput, Select, Combobox, Checkbox,
Switch, DatePicker and FileUpload) takes the same `FieldOptions` and wraps
itself in `Field`. So a label, a description, an error, `required`,
`invalid`, `disabled` and `readOnly` look and behave the same everywhere.

You rarely use `Field` directly. Reach for it when you build a control of
your own and want it to line up with the rest of the form.

## Label and description

Every field needs a visible `label`: a noun for the value, in sentence case,
without a colon. `description` adds what the label can't say in a few words,
such as a format or what the value is used for.

</ExampleBlock>

## Errors

Set `invalid` and give `errorText`. The error replaces the description, the
control's outline turns negative, and screen readers hear the error with the
control. Say what to do, not what went wrong.

  <ErrorOutput client:load />
</ExampleBlock>

## Required

`required` adds an asterisk to the label and sets `required` on the control,
so the browser and screen readers know too. When most fields in a form are
required, mark the optional ones instead.

  <RequiredOutput client:load />
</ExampleBlock>

## Disabled and read-only

Disabled fields can't be focused or changed, and their value isn't submitted:
use them for settings that don't apply right now, and say why. Read-only
fields show a value people can read, select and copy, but not change, on a
muted surface.

## Custom controls

(`Field.Input`, `Field.Textarea`, `Field.Select` from `@ark-ui/solid/field`).
They pick up the label, description, error and state from the field.

## Accessibility

- The label is a `<label>` pointing at the control, so clicking it focuses the
  control and screen readers announce it as the control's name.
- The description and the error text are linked with `aria-describedby`; the
  error is linked only while `invalid`.
- `invalid` sets `aria-invalid` on the control. The error colour is never the
  only signal: the error text and its icon say it too.
- The asterisk is hidden from screen readers, which hear "required" from the
  control itself.
- A field without a visible label must get an `aria-label`.

## Props

`FieldOptions`, taken by every field:

| Prop          | Type                                                 | Default |
| ------------- | ---------------------------------------------------- | ------- |
| `label`       | `JSX.Element`                                        |         |
| `description` | `JSX.Element`; hidden while `invalid`                |         |
| `errorText`   | `JSX.Element`; shown only while `invalid`            |         |
| `required`    | `boolean`                                            | `false` |
| `invalid`     | `boolean`                                            | `false` |
| `disabled`    | `boolean`                                            | `false` |
| `readOnly`    | `boolean`                                            | `false` |
| `id`          | `string`; the control's id (generated when left out) |         |

`Field` also takes `class` (for the wrapper) and `children` (the control).
